Compatibility

OSR2.00 is compatible with the Virus rack classic.

 

Installation

Please perform the following steps to update your Virus. If you are not familiar with the update procedure, please read the corresponding chapter in the user's manual.

The following files are located in the /OS/ folder.

  • Load first_rs_200.mid resp. first_rt_200.mid into your Virus. Proceed as stated in the display.
    This file contains the new operating system.
  • Load OSR_second1024.mid into your Virus. Proceed as stated in the display.
    This file contains the ROM sounds.

 

 

 

Remarks

 

S/T OS Version

On power up, the Virus shows not only the OS version but a little S or T in the right corner. This letter indicates the hardware revision of your Virus. From the next update on, there will be two different OS files. Please make sure that you install the right file. The procedure is save though, attempts to install an incompatible update will be quit with an error message.

  • first_rs_200.mid is to be installed on machines showing an "S" on the right corner of the startup screen.
  • first_rt_200.mid is to be installed on machines showing an "T" on the right corner of the startup screen.

 

There is no quality or performance difference in the two hardware revision.

 

Optional installation of the OS in chunks

Huh? There are two folders now: "OS" and "OS chunks"

From now one you can choose from one big OS MIDI file or several chunks. Some hardware sequencers are not able to handle a MIDI file of the Virus OS's size. Users who discovered that their hardware sequencer doesn't fulfil the memory requirements for the Virus OS might want to try to install one chunk after the other. All other users can stick with the old method - it's quicker and the Virus doesn't sound different in the end :-)

The special version is locate in the /OS chunks/ folder

Please note that some sequencers are not compatible with the "chunks" version.

How to install an OS which consists of chunks?

Load and install one chunk after the other. It is important that you install the files in the right order. The order is:

part1.mid

part2.mid

part3.mid

part4.mid

part5.mid

part6.mid

...etc

DISCLAIMER: The chunks won't work with some sequencers. As soon as the Virus is receiving an OS dump, it doesn't accept any other data. It will terminate OS update, if other data (such as a reset message for instance) appear. Some sequencers send reset messages, as soon as a song is being loaded.
So why using the this version at all? The Virus OS is rather big for a MIDI file and some older sequencers are not capable of dealing with such an amount of data. Their RAM is simply too small. Uploading the OS in chunks overcomes this limitation.

 

New Features

 

Below is a brief version history with bugs and improvements.

 

 

Version History OSR

 

OS 2.00

New Features:

- Phaser
- Additional ring modulator in the FX section

Please note that the new FX might change the sound of existing patches in the Virus. Some of the patches in the ROM section of the Virus rack classic already have phaser setting (which were disabled until OS2.0). In case you're in the middle of a production and you prefer those sounds to stay as they are, please disable the phaser for each single/multi patch manually.

OS 1.51

- Bank Change didn't work as expected (fixed)

OS 1.50

Improvements/new features:

- 1024 internal sounds. The second file, which comes with this update contains the new sounds
- Noise free switching in between patches.
- The Definable destinations are sorted alphabetical now

- The default SysExID has been changed to 1.


OSR 1.03

Internal improvements

OSR 1.02

Improvements

- The behavouir of the arpeggiator in combination with the audition button has been improved
- Syncphase is available for LFO3 via the menus
- Auto repeat has made available to the scroll buttons
- Globals switches for the arpeggiator and Delay/Reverb (see Global parameters)

OSR 1.01

Bugfixes and improvements

- LFO1 LED showed the content of LFO2 and vice versa
- The demosong sounded different to the one on our website
- Some delay/reverb algorithms weren't accessable via the menu
- Encoder handling of bipolar parameter has been improved
- Switching in between two patches with both arpeggiator hold enabled has been improved
- Loads of little enhancements

New Functions in OSR1.01

- The alert "SOUND EDITED!" which appears when you switch in between multi mode patches
and one sound has been edited can be disabled in

ARP/CTRL >>> SYSTEM >>> MEM PROTECT

OFF Memory protection is off
WARN Memory protection is off and warnings are disabled
ON Memory protection is on and warnings are on

OSR 1.0

Initial release
